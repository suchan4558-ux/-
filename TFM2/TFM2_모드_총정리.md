표기: 결정 표는 "항목 | 결정 | 이유". 미정은 각 장 끝 "미정"에 모음(Terminator 개편은 4-4 진행 순서 1). 판 = 한 세트, 경기 = 내 팀의 한 경기(2~3판).

# 2. 게임 자동 밸런스패치

## 2-1. 게임 규칙

| 항목 | 내용 | 확인 |
|---|---|---|
| 패치 기록 | 챔피언, 항목, 이전 값, 바뀐 값, 버프 여부. 크기 등급 없음 | 실행 파일 |
| 한 단계 크기 (강) | 기본 스탯 = 원래 값의 20%, 스킬 수치 = 4% (예: 공격력 100 → 120) | 패치 기록 |
| 2단계 | 특수 보정은 한 번에 2단계(40%). 누적 캡에서 잘림 (예: 증인 공격력 100 → 140, 소총수 100 → 70 = 캡 0.7) | 패치 기록 |
| 변경 폭 코드 | (누적 캡 최대 − 최소) × 단계 × 배수 × change_rate_multiplier | 실행 파일 (0x141483b00, 0.7.1) |
| 패치 이유 | 딜 과다, 너무 단단함, 회복 과다, 초반 강세, 후반 강세, 딜 부족, 너무 약함, 회복 부족, 초반 약세, 후반 약세, 안 뽑힘 | 실행 파일 |
| 바꿀 수 있음 | 데이터베이스의 25개 값과 `patch_setting`(누적 캡), 새 게임 옵션(강도·주기) | — |
| 바꿀 수 없음 | 고르는 기준, 단계 크기 (실행 파일 하드코딩) | — |

패치 문구 → 보정 종류 (2단계):

| 문구 | 보정 |
|---|---|
| "정말 오랫동안 무대에서 모습을 감추고 … 확실하게 밀어줍니다" | 장기 미선택 버프 |
| "메타의 중심에 너무 오래 …", "꽤 오랫동안 밴픽 단골 …" | 메타 고착 너프 |
| "여러 패치에 걸쳐 계속 상위권 …", "여러 패치째 부진 …", "꽤 오랫동안 좋은 성적을 내지 못하고 … 확실히" | 반복 패치 보정 |

|---|---|---|
| 패치 강도 / 주기 | 강 / 강 | 챔피언이 92명이라 승률 바닥 챔피언의 패치 차례가 너무 늦음 (사용자). 주기를 늦추고 패치 대상을 늘려도 챔피언 한 명이 바뀌는 간격(판 수)은 같아 AI에는 거의 의미 없고, 메타 고착·반복 보정(패치 수로 셈)만 늦어져 이 장의 결정을 다시 해야 함 |

| 강 기본 너프 (9, 11번) | +2 (대형 6, 소형 5) | 표 아래 |
| 약·보통 개수 (1~8번) | 기본값 | 강/강에서 안 쓰임 |
| 메타 고착 보정 (13~16번) | 기본값 | 붙는 빈도를 예측할 수 없어 버프 쪽 차이는 기본 너프로 보정함 |
| 장기 미선택 버프 (17~21번) | 기본값 | 계속 바닥인 챔피언에게 가는 항목이라 내리지 않음. 대상 고르는 기준은 모름 (2-4) |
| 반복 패치 보정 (22~25번) | 기본값 | 수정 Terminator로 돌려 보기 전엔 판단 불가 (2-4) |
| 누적 캡 (`patch_setting`) | 기본값 | 2단계 보정 한 번이면 공격력이 캡에 닿음 → 연속 패치·인플레이션을 막는 상한 역할. 바꿀 근거 없음 |

강 기본 버프 +1 이유 (숫자는 2-2):
- 1.0부터 버프는 전부 직전 픽률 4% 이하 챔피언에게 감 → 게임은 대상을 제대로 고름
- 바닥(픽률 2% 미만) 챔피언은 패치마다 23~40개인데 버프는 3~6개. 0.1~1.1에서 바닥 2번 이상이고 1.2까지 버프 0번인 챔피언 21개 → 버프 자리 부족
- 게임이 "오래"의 기준으로 3패치를 씀(메타 고착·반복 보정 시작) → 바닥 챔피언이 3~4패치 안에 버프 차례가 오는 수준. 3패치면 +2, 4패치면 +1~2 → 낮은 쪽
- 21개는 원본 Terminator 기록이라 부풀려졌을 수 있고, 부족하면 나중에 올리면 됨
- 장기 미선택(17~21번)만 올리면 2단계라 너프와 양이 어긋남 → 기본 개수로 올림

강 기본 너프 +2 이유 (숫자는 2-2):
- 버프와 같이 +1 (비중 유지) + 기존 버프 쪽 차이 보정 +1
- 단계 수 4패치 합 버프 31 / 너프 22 → 패치당 버프가 약 2.25단계 많음. 대부분 장기 미선택 2단계(1.1·1.2에서 6명 × 2단계)가 너프 짝 없이 들어간 것. 캡 때문에 실제 차이는 더 큼(공격력 버프 +40% / 너프 −30%)
- 장기 미선택을 내리면 바닥 챔피언 버프와 반대, 메타 고착 시작을 당기면 빈도 예측 불가 → 매 패치 1단계씩 확실히 들어가는 기본 너프로 보정
- 너프 대상 충분 (1.1 밴률 50% 넘는 챔피언 10개 가까이)
- 4패치뿐이고 애매한 판정(에스퍼·마검사)이 있어 보정은 +2가 아니라 +1
- 예상 (기록 평균 + 늘어난 자리를 1단계로, 대형·소형이 번갈아 온다고 가정): 버프 기본 평균 4.5 + 장기 미선택 1.25 = 약 5.75개·8.75단계, 너프 기본 평균 5.5 + 메타 고착 0.5 = 약 6개·7.5단계 → 차이 약 1.25단계 남음 (2-4)

| 항목 | 내용 | 언제 |

## 4-1. 지금 픽 점수

- 픽 점수 = 아래 16개 항목을 배율 없이 그냥 더한 값 (0x180077a54). 순서는 로그 형식 문자열(0x1800f912c) 순서 = `draft-log.txt` 순서

항목별 계산과 결정:

- 번호는 위 표 번호. "확인" = DLL에서 계산을 직접 봄
- 신뢰도는 전부 판/(판 + N), N = `full_confidence` 100. 판은 버전별 기록을 최신부터 더하다 누적 ceil(N)판에서 자른 값

공통

| 항목 | 결정 | 이유 |
|---|---|---|
| 10판 컷 | Terminator·Toolbox 둘 다 10 (Toolbox config 15 → 10, Terminator는 DLL 하드코딩 10) | 다르게 둘 근거 없음. 판/(판 + N) 보정이 이미 적은 판수를 줄이므로 컷은 낮을수록 정보 손실이 적음 |
| 꺼진 항목 (4 new-role, 5 moved, 8 direct, 11 tactics) | 항상 0 | 포지션 없는 모드. 포지션·듀오·전술도 같은 이유로 제거 |

1 강함
- 계산: 기준 = (변경 전 승 + 50)/(변경 전 판 + 100), 강함 = logit((변경 후 승 + 100 × 기준)/(변경 후 판 + 100)). 각 10판 미만이면 그쪽 기록 제외. logit = ln(승률 ÷ (1 − 승률)), 승률은 0.01~0.99로 자름 (0x1800978e0, `log`). logit 변환은 원본 DLL도 같음. 확인
- 이유: 기존 식은 비중 합이 100%보다 작아 0~100판 구간에서 점수가 내려갔다 오름. 새 식은 변경 전 → 변경 후로 자연스럽게 옮겨감

2 패치
- 계산: 부호 × 크기 × 100/(변경 후 판 + 100). 크기 = 아래 분류로 고른 `patch_small` / `patch_large` 값 그대로. 확인
- 줄어드는 속도 이유: 변경 전 비중(강함 공식)과 같은 속도로 줄어야 보정이 먼저 사라지지 않음
- 실제 동작: 변경 후 판이 잘린 값이라 패치 점수가 끝까지 약 47%(인기 챔피언 약 35%) 남음 (0x18008c6fe → 0x1800845ef, 4-4)
- 크기 분류: 그 패치에서 바뀐 기본 스탯(`stat.*`: 공격력·주문력·체력·방어력·마저·이속) 중 \|바뀐 값 − 이전 값\| ÷ 이전 값의 최댓값이 29.5% 이상(이속은 14.75%)이면 2단계 → `patch_large`, 아니면 1단계 → `patch_small`. 기본 스탯이 없으면 1단계. 2단계 = 1단계 × 2
- 크기 분류 이유:
  - 게임은 스탯 종류와 상관없이 같은 비율(1단계 20%, 2단계 40%)로 바꿈(2-1). 기존 분류는 스탯 종류(원거리 공격력 대 5, 마법사 주문력·탱커 체력 중 3, 그 외 소 1)로 나눠 같은 20% 패치가 1~5점으로 갈리고 2단계는 구분 못 함
  - DLL은 `stat.*` 항목의 값만 받음(스킬·성장·기본 공격 항목은 버림) → 스킬 계수로 2단계를 잡을 수 없음
  - 줄 수는 단계가 아니라 이유 개수를 따라감(0.1 오우거·수인 1단계 5줄). 변화율 합은 이유 두 개인 1단계(오우거 20% × 3)가 커짐 → 둘 다 기준으로 못 씀
  - 캡에 잘린 2단계(아마존·독침술사 1.2, 닌자 1.1: +17%)는 1단계로 읽히지만 실제로 바뀐 양이 1단계라 영향과 맞음
  - 29.5%: 1단계 최대(캡 0.7배 → 0.9배 = 28.6%)와 캡 걸린 2단계(−30%, 체력 +30%) 사이
  - 놓치는 것: 2단계의 스킬 계수 2배, 이유 개수

3 숙련도
- 계산: 팀 5명 중 최고값 (케이브 0x18008cae7, 선수별 표 5칸 중 max). 표 값 = `mastery_share` ÷ 100 × 게임 숙련도 보너스를 확률로 만든 뒤 logit (0x1800598ac에서 ÷100, 표 만드는 반복문 0x18000ee70에서 logit). 확인 (게임 숙련도 보너스 값 자체는 게임 쪽)
- 결정: `mastery_share` 10 (70대 +0.5 / 80대 +1 / 90 이상 +1.5)
- 이유: 숙련도 규칙(3-3)으로 거의 모든 챔피언에 숙련도가 붙어 비중을 낮춤

4 new-role: 항상 0 (DLL 수정). 확인

| 항목 | 결정 | 이유 |
|---|---|---|
| 계산 방식 | 추적 방식 (아래) | 패치 전 기록을 실제 판수만큼 믿고, 패치가 클수록 새 기록 쪽으로 빨리 옮겨 가고, 패치를 여러 번 받아도 앞 기록을 이어 씀. 가짜 게임 시험(챔피언 92명, 패치 12번, 아래 값을 진짜 값으로 둠, 패치당 38판)에서 상위 10명의 진짜 승률이 평균보다 +2.1%p (이번 패치 승률만 +1.7%p, 지금 DLL과 비슷한 방식 +1.2%p, 진짜 실력을 다 알면 약 +5.5%p) |
| 값 | 아래 표 | `TFM2/통계`(원본 Terminator)로 잰 값. 개편 DLL로 돌린 뒤 같은 방법으로 다시 잼 |
| 픽·밴 횟수 | 안 씀. 승패 기록만 씀 (픽 횟수는 판수로서 기록을 믿는 정도에만 들어감). 조합의 예상 승률도 같음 | 이 리그의 픽·밴은 거의 AI가 해서 AI 자신의 판단임. 넣으면 AI가 세다고 본 챔피언이 그 횟수 때문에 더 세게 잡혀, 실제 성적과 상관없이 쏠림이 커짐 (2-2: 너프받은 오우거 밴률 14% → 66%). 밴 때문에 판수가 적은 챔피언은 오차 범위로 처리됨 |

추적 방식 (챔피언마다 추정 승률과 오차 범위를 들고, 패치 0.0부터 지금 패치까지 차례로. 오차 범위·판수 오차는 %p 단위):

| 단계 | 계산 |
|---|---|
| 시작 | 추정 승률 50%, 오차 범위 = 승률 편차 |
| ① 패치가 지남 (모든 챔피언) | 추정 승률 = 50% + 남는 비율 × (추정 승률 − 50%). 오차 범위² = 남는 비율² × 오차 범위² + (1 − 남는 비율²) × 승률 편차² |
| ② 그 패치에서 바뀐 챔피언 | 추정 승률에 패치 효과를 더함 (버프 +, 너프 −). 오차 범위²에 효과의 오차 범위²를 더함. 1단계·2단계는 패치 크기 분류(4-1 2 패치)로 |
| ③ 그 패치 경기로 고침 | 판수 오차² = 2500 ÷ 그 패치 판수. 옮기는 비율 = 오차 범위² ÷ (오차 범위² + 판수 오차²). 추정 승률 = 추정 승률 + 옮기는 비율 × (그 패치 승률 − 추정 승률). 오차 범위² = 오차 범위² × (1 − 옮기는 비율). 진행 중인 패치도 그때까지 경기로 |
| 밸류 | 지금 패치까지 마친 추정 승률 |

| 값 | 결정 | 근거 (`TFM2/통계`) |
|---|---|---|
| 승률 편차 | 3.2%p | 패치마다 (기록 승률의 분산 − 판수 오차의 평균 분산)을 구해 20판 이상 챔피언 수로 가중 평균 |
| 남는 비율 | 0.47 | 그 패치에 안 바뀐 챔피언(두 패치 모두 20판 이상)의 연속 두 패치 승률 공분산 4.9%p² ÷ 승률 편차². 이 값이면 다섯 패치를 합친 편차가 2.10%p로 실제 2.16%p와 맞음. 패치 쌍별 공분산은 13.9 / −3.7 / 5.4 / −0.5로 흔들림 |
| 패치 효과 | 1단계 0.5%p / 2단계 1%p | 패치 전 승률을 판수 오차만큼 50% 쪽으로 당긴 뒤 패치 후 승률과 비교(패치 후 10판 이상 27건). 2단계 = 1단계 × 2로 두면 1단계 0.44%p (95% 범위 −1.2 ~ +2.1%p) |
| 효과의 오차 범위 | 1단계 1.3%p / 2단계 2.6%p | 위 효과를 빼고 남는 챔피언별 차이 1.3%p. 2단계는 두 배 (게임이 스탯을 두 배로 바꿈) |

- 밸류 차이는 대부분 ±1%p 안 (기록이 적어 확실히 아는 게 적음)

조합 (조합·피해유형 중 조합):

| 항목 | 결정 | 이유 |
|---|---|---|
| 재는 단위 | 우리 팀 유형 구성 전체 (우리 태그 6가지별 인원수) | 구성을 쪼개지 않고 전체로 봄 |
| 재는 것 | 그 구성을 포함한 팀들이 밸류로 예상한 승률보다 실제로 얼마나 더 이겼나 | 구성 승률에는 들어간 챔피언의 밸류가 섞여 있어, 빼지 않으면 밸류를 두 번 셈 |
| 기록 범위 | 시즌 전체. 패치가 지나도 줄이지 않음 | 패치는 챔피언 6~11명을 바꿀 뿐 유형 전체를 바꾸지 않고(2-2), 바뀐 챔피언의 몫은 밸류가 가져감 (추론, 기록으로 확인 안 함) |
| 기록이 적을 때 | 0 쪽으로 당김. 기록이 쌓일수록 덜 당김 | 기록이 없으면 "밸류 말고 더하는 게 없다"가 가장 합리적인 짐작 |
| 드래프트 도중 | 후보를 넣은 지금까지의 부분 구성으로 같은 식 (5픽이면 최종 구성) | 남은 자리가 채워진 경우들을 기록 비율로 평균한 것과 같음. 최댓값(남은 자리를 가장 좋게 채운다고 봄)은 마지막 픽 전까지 조합이 작용하지 않고, 같은 확률은 남은 자리를 엉뚱하게 채우는 경우까지 똑같이 섞음 |
| 조정 | 돌려 봤을 때 조합 점수가 다 0 근처면 조정 | — |

- 경기가 끝날 때마다 팀마다: 예상 승률 = 50% + (우리 팀 다섯 명의 "밸류 − 50%" 합) − (상대 팀 다섯 명의 "밸류 − 50%" 합). 밸류는 그 경기 직전 값. 실제 결과(승 1, 패 0) − 예상 승률을 그 팀이 포함하는 모든 구성 칸에 더하고, 칸마다 팀 수를 1 늘림
- 드래프트 때: 조합 점수 = (그 칸에 쌓인 차이 합) ÷ (그 칸의 팀 수 + 0.25 ÷ 구성 편차²) × 100 (%p). 구성 편차(구성끼리 실제 승률 차이)는 미정
- 팀 수 = 그 구성을 포함한 팀이 나온 횟수 (한 경기에서 두 팀 다 해당하면 2)
- 포함 = 최종 다섯 명 안에 지금까지 고른 유형이 고른 인원 이상씩 있는 팀. 나머지 자리는 무엇이든 상관없음 (예: 탱커 1·원딜 1을 골랐으면 탱커 1명 이상·원딜 1명 이상인 팀 전부, 탱커 2를 골랐으면 탱커 2명 이상인 팀만)
- 예상 승률 근거: 밸류가 50%에서 벗어난 만큼이 그 챔피언이 팀 승률에 보태는 몫. 밸류 차이가 대부분 ±1%p 안이라 그냥 더해도 logit 변환과 거의 같음
- 경기별 기록: DLL이 경기마다 버전·양 팀 챔피언·밴·승패(`struct Game`)를 읽음 (문자열로 확인, 기계어는 미확인)

진행 순서:
1. 새 픽 점수 다섯 항목마다 계산 방법과 크기 정하기
2. 정한 계산을 Python으로 짜기 (3에서 고친 DLL을 에뮬레이터로 실행한 결과와 비교하는 기준)

4. config·총정리(4-1~4-3) 한 번에 반영, 이 절은 지움
5. 게임 로그(`draft_log=true`)로 확인 (밴 포함)

## 6-7. 빌드 선택 점수

| 항목 | 결정 | 이유 |
|---|---|---|
| 구간 통계 | 초반 = 1·2·3코어, 중반 = 2·3·4, 후반 = 3·4·5 (통계·선택 동일) | — |
| 점수 안 쓰는 칸 | 신발, 1코어 고정 | 후보가 하나 |
| 1코어 예외 기록 | 2~5코어 기록은 원래 태그(Mage/Tank)에 합산 | 같은 계열 템을 씀 |
| 공식 구조 | Terminator와 같은 방식 (아래) | 점수로 고르는 도구라 Terminator와 성격이 같음 |
| 변경 기준 | 그 아이템 수치가 마지막으로 바뀐 시점 (자동·수동·가격 포함, 하위템만 바뀐 건 제외, 게임 버전만 오른 건 제외) | Terminator와 같은 기준 |
| 10판 컷 | 10 | Terminator·Toolbox와 같음 (4-1 공통) |

```
대상: 챔피언 c, 아이템 i, 구간 s / g, w = 그 구간에 그 템을 산 판수·승수
기준   = (태그 변경 전 w + N/2) / (태그 변경 전 g + N)           ※ 변경 전 10판 미만이면 0.5
태그   = (태그 변경 후 w + N × 기준) / (태그 변경 후 g + N)        ※ 10판 미만이면 w, g = 0
챔피언 = (챔피언 변경 후 w + N × 태그) / (챔피언 변경 후 g + N)    ※ 10판 미만이면 w, g = 0
패치   = 부호 × 크기 × N / (태그 변경 후 g + N)                   ※ 버프 +1 / 너프 −1 / 변경 없음 0
점수   = (챔피언 − 0.5) × 100 + 패치 + 탐색 + 무작위              (1점 = 승률 1%p)
탐색   = AI 팀만, 10판 미만이면 전부, N판에서 0 / 플레이어 팀 0
무작위 = AI 팀만, 균등분포 / 플레이어 팀 0
```

- 태그 승률 = 같은 태그 챔피언 전원 기록 합산
- 변경 전 기록 = 그 이전 변경부터 마지막 변경 직전까지, 최신부터 약 N판
- 후반 템은 최소 3개 있어야 칸이 안 빔

| 가격 | 자동 패치에서 안 바뀜 (수동 핫픽스만) |
| 하위템 | 완성템 2개 이상이 같은 방향이면 하위템을 대신 패치 |

- 크기가 연속값이라 챔피언처럼 1단계/2단계로 못 나눔. 소스를 직접 빌드하므로 실제 바뀐 비율을 읽을 수 있음 → 6-7 패치 점수는 이걸로 정할 수 있음

## 6-9. 챔피언 수정 (보류)

- 같은 id `.data_champion`으로 덮어쓰기. 데이터형 32명은 계수만, 기본 60명은 스킬을 데이터로 새로 작성
- 지금 있는 `.data_champion`: 저장소 `TFM2/게임데이터/챔피언_데이터/` 26개 (모드 20명 + 업데이트 6명). 나머지 업데이트 6명(모래술사, 점성술사, 작살잡이, 검투사, 포격수, 최면술사)은 mods 폴더에 파일 없음, 데이터 위치 미확인
- 데이터로 불가: 드루이드, 네크로맨서, 환영술사, 강시, 흑마술사, 방패병, 음유시인, 늑대인간, 부두술사, 얼음술사
- 후보: 캔디 젤 계수 / 공격력 계수 Tank를 체력 계수로 / Assassin 일부 주문력 계수
